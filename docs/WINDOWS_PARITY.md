## 必须在 Windows 上完成的检查

- x64 和 ARM64 各自运行原生应用，不以交叉编译代替 ARM64 实际运行。
- 使用可信签名安装 MSIX，再升级到相同应用身份的下一版本。
- 在中文路径、UNC、长路径、符号链接和大小写敏感目录中运行仓库操作。
- 验证高对比度、键盘导航、屏幕阅读器、中文输入法、多屏 DPI 和长翻译文本。
- 验证认证失败、Hooks 阻止提交、Git 不存在、文件监控溢出、克隆取消和应用退出。
- 对存在新提交、未提交修改、未跟踪文件或锁定状态的 Worktree 进行清理，确认内容保留。

## 工作台操作流程对齐

Windows 工作台以 macOS 的选择和操作流程为基准，平台适配仅调整原生控件、快捷键与系统集成。核心测试通过不代表交互验收完成。

- 仓库导航、历史与详情保持三栏职责。打开或切换仓库后不自动进入提交编辑器。
- 选择历史提交只显示详情。选择“未提交的更改”才显示提交工作区，两者互斥，切换时保留当前仓库的提交草稿。
- 提交工作区上下同时展示未暂存与已暂存差异，分隔条可调整高度，空暂存区自动收起。文件与代码块直接提供暂存或取消暂存操作，未跟踪文件点击后暂存。写操作刷新两个分区，不改变当前选择。
- 提交或创建 Stash 成功后清空详情选择，未提交的剩余修改保留。历史详情中不能通过提交快捷键触发隐藏编辑器的提交。
- 历史区持续显示提交记录。当前分支按钮打开本地与远程分支选择器；标签、Stash 和版本比较通过仓库菜单进入。关联 Worktree 从侧栏进入，不另占历史标签页。
- 新建分支与标签放在对应提交的上下文菜单中，明确使用被右键点击的提交。远程分支选择与 macOS 一致，以 Detached HEAD 检出。
- 同时选择两个提交可比较差异。父提交链接可继续查看历史，并通过返回按钮回到原提交。接近历史底部时自动分页，刷新列表时保留仍有效的选择。
- Stash 使用独立的列表、预览和操作弹窗，查看或处理 Stash 不替换主工作台的历史选择。
- 选择切换立即取消旧的详情请求，旧仓库或旧提交的异步结果不得覆盖新工作区。

新增 `FoldGit.Workbench.Tests`，直接编译并测试应用使用的 ViewModel，在独立临时设置目录和真实 Git 仓库中验证选择互斥、异步取消、暂存刷新、比较保持、提交完成与仓库隔离。云调试完整构建和双架构 CI 均运行这些测试。原生 XAML 构建与界面验收须在 Windows 上另行完成。
