Fold 是什么意思

  1. 仓库散落各处

    项目散在不同目录里，多数工具一次只能看一个仓库，切换全靠记忆。

  2. 按目录或分组折叠

    导入目录自动成组，也能把任意位置的仓库收进同一组。不移动任何文件夹。

  3. 工作树收在仓库之下

    自动发现工作树，带着分支名折叠在仓库下方。新建、锁定、合并收尾，一处完成。

  4. 不活跃的，再折一层

    不活跃的仓库再折一层，活跃的始终在眼前。配合过滤和排序，几十个仓库也一目了然。

为什么做 FoldGit

IDE 渐渐不必打开了，
但代码仍需要有人看过。

01

AI 写代码，人来把关

代码越来越多由 Agent 生成，看改动常常不必再打开 IDE。但生产代码仍要有人过一遍：改了哪些文件、哪几行、有没有越界。

02

一个顺眼又轻快的窗口

所以需要一个打开即用、专注看清改动的 Git 界面：提交图、差异、暂存、提交，并且符合 macOS 的视觉习惯。

03

为什么另起炉灶

现有 Git 客户端很难同时做到美观、简洁、轻量。方向相近的项目也有，本想参与，但交互和底层都已偏离太远，不适合在原项目里改，于是重新开始。

差异在哪里

少一点负担，
多一点秩序。

为多项目而生

所有仓库常驻侧边栏，按目录或分组折叠，支持多种排序与过滤；可直接导入本地目录或克隆远程仓库。

工作树是一等公民

自动发现，检查分支占用，完成时合并并清理；冲突在原生弹窗里处理。

约 4 MB

SwiftUI 与 AppKit 原生实现，不含 Electron；同类 Electron 应用常上百 MB。

快，而且不打扰

搜索在后台进行，复用索引、分页返回，新输入即取消旧查询；自动抓取按仓库定时，只下载不合并。

直观的操作逻辑

差异随窗口宽度自动切换单栏或双栏，逐块暂存，提交信息模板一键填入，没有多余弹窗。

像 macOS 本身

采用 macOS 26 液态玻璃与系统控件，原生支持亮暗色和八种界面语言。
